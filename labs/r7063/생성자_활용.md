# C++ 핵심 개념 정리: 생성자 초기화와 스마트 포인터

본 문서는 `Department`, `Faculty` 예제를 다루며 질문했던 C++의 주요 개념들을 정리한 학습 자료입니다.

---

## 1. 생성자: 멤버 초기화 리스트 (Member Initialization List)

클래스의 객체가 생성될 때 멤버 변수들에 값을 넣는 방법은 크게 '초기화 리스트'와 '대입' 두 가지가 있습니다.

### ❌ 권장하지 않는 방식 (생성자 내부 대입)
```cpp
Department::Department(const std::string& name, std::shared_ptr<Faculty> faculty) {
    this->name = name;       // 1. 빈 껍데기로 먼저 만들어짐
    this->faculty = faculty; // 2. 그 위에 값을 덮어씀 (대입)
}
```
* **문제점:** 객체 생성 시 쓰레기값(또는 기본값)으로 초기화한 뒤 다시 값을 대입하므로 비효율적입니다. `const`나 참조자(`&`) 멤버는 이 방식으로 값을 넣을 수 없습니다.

### ⭕ 권장하는 방식 (멤버 초기화 리스트)
```cpp
Department::Department(const std::string& name, std::shared_ptr<Faculty> faculty) 
    : name(name), faculty(faculty) { 
    // 생성과 동시에 값이 확실하게 세팅됨
}
```
* **장점:** 클래스 객체가 메모리에 할당되는 그 순간에 값을 바로 넣습니다. 더 빠르고 안전합니다. C++의 표준 권장 사항입니다.

### ⚠️ 주의: 일반 멤버 함수에서는 사용 불가
멤버 초기화 리스트(`: 멤버(값)`) 문법은 오직 **생성자**에서만 쓸 수 있습니다.
`setFaculty()`처럼 이미 만들어진 객체의 값을 나중에 수정하는 '일반 함수'에서는 쓸 수 없으며, 반드시 중괄호 내부에서 대입(`=`) 연산자를 사용해야 합니다.

```cpp
void Department::setFaculty(std::shared_ptr<Faculty> f) {
    this->faculty = f; // 이미 존재하는 객체이므로 대입만 가능!
}
```

## 2. 값(Value) vs 포인터(Pointer)와 공유(Sharing)

데이터를 다룰 때 직접 값을 다루는 것과 메모리 주소(포인터)를 다루는 것에는 명확한 용도 차이가 있습니다.

* **값(Value)으로 다루기 (`vector` 등):** 
  원하는 데이터를 자신만의 '복사본'으로 갖게 됩니다. 다른 곳에서 값을 바꿔도 내 것은 변하지 않습니다.
* **포인터(Pointer)로 다루기 (`Faculty` 등):**
  여러 학과(`Department`)가 각자 다른 `Faculty`(공과대학)를 가지는 것이 아니라, **하나의 원본 `Faculty`를 여러 학과가 함께 소속되어 공유**해야 합니다. 이처럼 "하나의 원본을 같이 가리킬 때" 포인터를 사용합니다.

## 3. 스마트 포인터와 `std::make_shared`

`std::shared_ptr`는 여러 객체가 하나의 원본 메모리를 공유하면서, 아무도 가리키지 않을 때 알아서 메모리를 지워주는(Garbage Collection) 똑똑한 포인터입니다. 이를 생성할 때 `std::make_shared`를 사용합니다.

### 문법 구조 완벽 해부

```cpp
auto faculty = std::make_shared<Faculty>("Computer Science", 10);
```

1. **`std::make_shared`의 역할:** 
   "메모리 상에 원본 객체를 딱 하나 안전하게 만들고, 이 객체를 가리키는 `shared_ptr`(스마트 포인터)를 반환해줘!"
2. **꺾쇠괄호 `< >` (타입 지정):** 
   어떤 형태의 객체를 생성할지 결정. 여기서는 `<Faculty>` 타입의 객체를 만듭니다.
3. **소괄호 `( )` (생성자 매개변수):** 
   해당 클래스의 생성자에 넘길 **초기값(재료)**들입니다. 여기서는 이름 `"Computer Science"`와 정원 `10`을 넘겼습니다.

### почему `new` 대신 `make_shared`를 쓰는가?
과거 C++ 방식처럼 `shared_ptr<Faculty>(new Faculty(...))` 형태로 만들면, 메모리를 두 번 할당해야 해서 느리고, 중간에 예외가 발생하면 메모리 누수(좀비 메모리)가 생길 위험이 있었습니다. `make_shared`는 한 번의 최적화된 메모리 포장으로 이 모든 위험을 방지하는 C++ 최신 표준의 권장 방식입니다.
